蓝桥杯练习：图像模糊处理

发表于 2024-04-08 更新于 2026-05-14 分类于 算法练习

题目描述

小蓝有一张黑白图像，由 $n \times m$ 个像素组成，其中从上到下共 $n$ 行，每行从左到右 $m$ 列。每个像素由一个 $0$ 到 $255$ 之间的灰度值表示。

现在，小蓝准备对图像进行模糊操作，操作的方法为：对于每个像素，将以它为中心 $3 \times 3$ 区域内的所有像素（可能是 $9$ 个像素或少于 $9$ 个像素）求和后除以这个范围内的像素个数（取下整），得到的值就是模糊后的结果。

注意：每个像素都要用原图中的灰度值计算求和。

输入描述

输入的第一行包含两个整数 $n, m$。

第 $2$ 行到第 $n+1$ 行每行包含 $m$ 个整数，表示每个像素的灰度值，相邻整数之间用一个空格分隔。

数据范围：$1 < n, m < 100$。

输出描述

输出 $n$ 行，每行 $m$ 个整数，相邻整数之间用空格分隔，表示模糊后的图像。

题目分析与解题思路

这是一道典型的矩阵模拟题目，主要考察对二维数组的操作以及边界条件的处理。

核心步骤

  1. 数据读取：读取图像的行数 $n$ 和列数 $m$，并将像素数据存入二维列表（矩阵）中。
  2. 创建副本：由于题目要求“每个像素都要用原图中的灰度值计算”，这意味着我们不能在原矩阵上直接修改，否则会影响后续像素的计算。因此，需要创建一个同样大小的结果矩阵。
  3. 遍历计算：
    • 遍历矩阵中的每一个像素点 $(i, j)$。
    • 对于每个点，检查其周围 $3 \times 3$ 的邻域。邻域的范围是行 $[i-1, i+1]$ 和列 $[j-1, j+1]$。
    • 边界处理：当 $(i, j)$ 位于图像边缘（第一行、最后一行、第一列、最后一列）时，$3 \times 3$ 邻域会超出矩阵边界。此时需要判断坐标是否合法（$0 \le k < n$ 且 $0 \le l < m$）。
    • 求和与计数：累加邻域内合法像素的灰度值，并统计像素个数。
    • 取整赋值：计算平均值（向下取整）并赋值给结果矩阵对应位置。

时间复杂度

由于需要对每个像素遍历其周围的 $3 \times 3$ 邻域，且 $n, m$ 最大接近 $100$，总运算次数约为 $100 \times 100 \times 9 = 9 \times 10^4$，远小于一般限制的 $10^8$，算法效率完全满足要求。

无尽的石头

发表于 2024-04-08 更新于 2026-05-14 分类于 算法笔记

问题描述

在一个古老的迷宫中，有一道无尽的通道。通道上每隔一定的距离就会有一块神秘的石头，石头上刻着从 1 开始的连续整数。从 1 号石头开始，每块石头的编号都比前一块大 1。

石头上的数字拥有特殊的意义。如果你站在编号为 $n$ 的石头上，并向前走，你将会瞬间移动到编号为 $n+x$ 的石头上，其中 $x$ 为 $n$ 的各位数字之和。

举个例子：
如果你站在编号为 16 的石头上，由于 $1+6=7$，所以下一步你会移动到编号为 $16+7=23$ 的石头上。

现在，会有多次询问，你需要对每个询问输出从 1 号石头出发到达指定编号石头的最少步数。如果无法到达，则输出 -1。

输入格式

第一行输入一个整数 $t$ ($1 < t < 100$)，表示有 $t$ 次询问。

接下来 $t$ 行，每行一个整数 $n$ ($1 \le n \le 10^5$)，表示目标石头的编号。

输出格式

对于每个询问，输出一行，表示从 1 号石头到达目标石头的最少步数。如果无法到达，输出 -1。

思路分析

本题属于模拟与图论建模的结合问题。

  1. 模型抽象：我们可以将石头编号看作图中的节点。从节点 $n$ 出发，下一步只能到达节点 $n + \text{digits_sum}(n)$。这实际上构成了一棵以 1 为根节点的树（或者说是单链分支的集合）。
  2. 可达性分析：由于路径是单向且确定的，对于任意节点 $n$，它的前驱节点是唯一的（如果存在），后继节点也是唯一的。从 1 号石头出发的路径是固定的。
  3. 预处理与查询优化：
    由于询问次数 $t$ 可能较多，且目标编号 $n$ 具有随机性，我们可以采用预处理的方式：
    • 从 1 开始模拟移动过程，记录沿途经过的每一个节点（石头编号）以及到达该节点的步数。
    • 使用一个列表 reachable_stones 记录路径上的所有节点。
    • 对于用户的每一次询问 $n$：
      • 如果我们当前的模拟终点已经 $\ge n$，直接判断 $n$ 是否在 reachable_stones 中。若在，输出下标（即步数）；若不在，说明永远无法到达（因为路径是严格递增的），输出 -1。
      • 如果模拟终点 $< n$，继续向后模拟计算，直到终点 $\ge n$ 为止，然后进行判断。

这种方法利用了路径的单调递增性，避免了重复计算。

算法笔记：缩位求和的迭代与递归实现

发表于 2024-03-27 更新于 2026-05-14 分类于 算法笔记

题目描述

在电子计算机普及以前，人们经常使用一种粗略的方法来验算四则运算是否正确，这种方法类似于“弃九法”。

例如： 验算 248 x 15 = 3720

  1. 对乘数和被乘数分别逐位求和，若结果为多位数则继续逐位求和，直到变为一位数。
    • 248 -> 2+4+8=14 -> 1+4=5
    • 15 -> 1+5=6
    • 乘积验算：5 x 6 = 30 -> 3+0=3
  2. 对实际运算结果逐位求和：
    • 3720 -> 3+7+2+0=12 -> 1+2=3
  3. 若两边结果一致（均为3），说明计算正确的可能性很大。

任务： 请编写一个计算机程序，对给定的数字字符串进行反复逐位求和，直到结果为一位数。

输入输出描述

输入描述：
输入为一个数字字符串，表示一个 $n$ 位数（$n < 1000$）。

输出描述：
输出一位数，表示反复逐位求和的最终结果。

算法思路

本题的核心逻辑是将数字各位相加，如果结果大于等于10，则重复该过程。这是一个典型的重复计算问题，既可以使用迭代（循环）实现，也可以使用递归实现。

代码实现

1. 迭代写法

迭代算法通过循环结构重复执行操作，直到满足终止条件。在本题中，终止条件是数字仅剩一位。

核心逻辑：

  1. 定义一个函数 num_sum 计算当前数字的各位之和。
  2. 使用 while 循环判断当前数字位数是否大于1，若大于1则调用函数更新数值。

```python
def num_sum(a):
“””计算数字 a 的各位之和”””
a = str(a)
res = 0
for i in a:
res += int(i)
return res

读取输入

num = input().strip() # 建议直接读取字符串，避免大整数转换开销，逻辑处理时保持字符串或转int视情况而定
x = int(num) # 原逻辑转int处理

迭代求解

while len(str(x)) != 1:
x = num_sum(x)

print(x)

注： 原代码中使用 int(input()) 接收输入。由于题目保证 $n<1000$，Python 支持大整数，此处转换无碍，但在处理超大数字时，直接作为字符串操作往往更优。

2. 递归写法

递归算法将问题分解为更小的子问题。对于本题，如果数字已经是一位，直接返回；否则计算各位和并调用自身。

核心逻辑：

  1. 基准条件： 如果数字长度为1，直接返回该数字。
  2. 递归步骤： 计算各位之和，将和作为参数调用自身。

```python
def num_sum(a):
“””递归计算缩位求和”””

# 将输入转为字符串以便判断长度和遍历
s = str(a)

# 基准情况：如果只剩一位，返回结果
if len(s) == 1:
    return int(s)

# 递归步骤：计算各位和并递归调用
res = 0
for i in s:
    res += int(i)
return num_sum(res)

读取输入并调用

num = input().strip()
print(num_sum(num))

方法对比

特性 迭代法 递归法
实现方式 使用循环结构 函数调用自身
代码可读性 逻辑直观，结构清晰 代码简洁，更贴近数学定义
内存消耗 通常较低，无栈帧开销 每次调用需分配栈空间，深度过大可能栈溢出
适用场景 适用于大多数线性重复任务 适用于问题可自然分解为子问题的场景

对于本题，由于输入位数 $n < 1000$，递归深度非常有限（因为数字和衰减极快，如1000位的9，第一次求和也仅为9000），因此两种方法均非常安全且高效。

题目描述

小蓝负责花园的灌溉工作。花园可以看成一个 $n$ 行 $m$ 列的方格图形，中间有一部分位置上安装有出水管。

小蓝可以控制一个按钮同时打开所有的出水管，打开时，有出水管的位置可以被认为已经灌溉好。每经过一分钟，水就会向四面扩展一个方格，被扩展到的方格可以被认为已经灌溉好。即如果前一分钟某一个方格被灌溉好，则下一分钟它上下左右的四个方格也被灌溉好。

输入描述

输入的第一行包含两个整数 $n, m$，表示花园的行数和列数。
第二行包含一个整数 $t$，表示出水管的数量。
接下来 $t$ 行描述出水管的位置，其中第 $i$ 行包含两个数 $r, c$，表示第 $r$ 行第 $c$ 列有一个排水管。
接下来一行包含一个整数 $k$。

数据范围：
$1 \le n, m \le 100$
$1 \le t \le 10$
$1 \le k \le 100$

输出描述

输出一个整数，表示 $k$ 分钟后被灌溉好的方格数量。

蓝桥杯练习：天干地支计算

发表于 2024-03-25 更新于 2026-05-14 分类于 算法笔记

题目背景

在中国古代，时间记录采用“干支纪年法”，即通过天干和地支的组合来表示年份。天干有十个，地支有十二个，它们按固定顺序搭配，循环记录年份。本题要求根据给定的公元纪年，计算出对应的天干地支。

思路解析

解决这道题的关键在于找出公元纪年与天干地支序列之间的数学映射关系。

1. 数据定义

首先，我们需要将天干和地支映射为列表（数组），索引从 0 开始：

  • 天干：甲、乙、丙、丁、戊、己、庚、辛、壬、癸。
  • 地支：子、丑、寅、卯、辰、巳、午、未、申、酉、戌、亥。

2. 寻找基准点

通过观察或查阅资料可知，公元 4 年恰好是“甲子年”。

  • 甲：天干列表索引 0
  • 子：地支列表索引 0

因此，我们可以将公元 4 年作为计算的基准点。

3. 算法推导

对于任意输入年份 year：

  1. 计算偏移量：offset = year - 4。这表示该年份距离基准年过去了多少年。
  2. 计算天干索引：由于天干有 10 个，循环周期为 10。
    • 索引 = offset % 10
  3. 计算地支索引：由于地支有 12 个，循环周期为 12。
    • 索引 = offset % 12

最后，根据计算出的索引在列表中取值并拼接即可。

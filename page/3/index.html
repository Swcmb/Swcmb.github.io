[LeetCode 525] 连续数组 + 滑动窗口优化详解

题目概览

  • 题目来源: LeetCode
  • 题目难度: ★★★☆☆
  • 标签分类: 数组、滑动窗口
  • 核心考点: 数组操作、滑动窗口优化

题意解析

  • 问题描述: 给定一个二进制数组，计算具有最多连续1的子数组的长度。
  • 输入格式: 一个字符串形式的二进制数组。
  • 输出格式: 一个整数，表示具有最多连续1的子数组的长度。
  • 样例分析:
    • 输入: “0110111”
    • 输出: 3
    • 解释: 子数组 “111” 包含3个连续的1，这是最长的。

算法思路（核心部分）

4.1 问题分析

  • 问题的本质是找出数组中连续1的最长子数组。
  • 关键观察点：连续1的子数组可以通过滑动窗口来处理。
  • 数据范围对算法选择的影响：由于是二进制数组，我们可以使用滑动窗口来高效地解决问题。

4.2 算法原理

  • 朴素思路: 遍历数组，对每个位置计算连续1的长度，然后找到最大值。
  • 优化路径: 使用滑动窗口来避免重复计算。
  • 算法选择: 滑动窗口算法，因为它可以在O(n)时间内解决问题。
  • 核心思想: 维护一个滑动窗口，当窗口内的1的长度增加时，更新最大长度。

4.3 算法原理（详细）

  • 初始化两个指针 i 和 j，分别表示窗口的起始和结束位置。
  • 初始化 max_len 为0，用来存储最大连续1的长度。
  • 遍历数组，移动 j 指针，如果遇到1，则增加窗口内的1的数量，否则移动 i 指针直到窗口内都是1。
  • 在每次移动 j 指针后，更新 max_len。

4.5 优化技巧

  • 空间优化：使用计数器 count 而不是额外的数组来存储连续1的数量。
  • 时间优化：通过滑动窗口，避免了重复计算。

6. 复杂度分析

  • 时间复杂度: O(n)，遍历数组一次。
  • 空间复杂度: O(1)，只使用常数额外空间。

  • 样例输入: “0110111”
  • 样例输出: 3

算法思路（核心部分）

4.1 问题分析

  • 问题的本质是找到一种最“倒霉”的情况，即国王尽可能多地选择士兵，却仍然凑不出 (k) 个小组。

4.2 算法原理

  • 朴素思路: 对每个职业进行排序，然后从人数最多的职业开始选择，直到组成 (k) 个小组。

  • 算法选择: 贪心算法，因为它能够保证在每一步都做出当前情况下最优的选择。

4.3 数学推导

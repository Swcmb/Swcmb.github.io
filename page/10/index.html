可以把这题记成一句话：

不是冒泡排序，而是“排列的环分解 + 最少任意交换次数”。

核心结论

把当前排列看成一个置换，分解成若干个环（循环节）后：

  • 每个长度为 k 的环，最少需要 k - 1 次交换；
  • 所以总答案就是：

[
\sum (k_i - 1) = n - m
]

其中 n 是元素个数，m 是环的个数。

为什么不是冒泡排序？

  • 冒泡排序交换的是相邻元素，对应的是逆序对数量。
  • 这道题允许交换任意两本书，所以求的是最少任意交换次数。

这两个题型完全不同。

为什么是环分解？

例如排列 3 1 2，减 1 后是 2 0 1：

  • 0 → 2
  • 2 → 1
  • 1 → 0

形成一个环：0 → 2 → 1 → 0

这个环长度是 3，所以最少交换次数是 3 - 1 = 2。

为什么长度为 k 的环要 k-1 次？

因为每次交换，最多只能让这个环里的一个元素真正归位（只有长度为 2 的环，才能一次让两个元素同时归位）。

所以：

  • 3 个元素成环，至少要 2 次；
  • 4 个元素成环，至少要 3 次；
  • 以此类推，k 个元素成环，最少 k-1 次。

总结成算法

  1. 把排列看成“位置 → 目标位置”的映射；
  2. 用 visited 找出所有环；
  3. 统计环的个数 m；
  4. 输出 n - m。

复杂度

  • 时间复杂度：O(n)
  • 空间复杂度：O(n)
    n <= 10^6，适合用 bytearray 优化内存。

一句话记忆

任意交换最少次数 = 元素总数 − 环个数。

给定 $n$，请问有多少种堆放货物的方案？

例如：当 $n=4$ 时，有以下 6 种方案：

  • $1 \times 1 \times 4$
  • $1 \times 2 \times 2$
  • $1 \times 4 \times 1$
  • $2 \times 1 \times 2$
  • $2 \times 2 \times 1$
  • $4 \times 1 \times 1$

问题：当 $n=2021041820210418$（注意有 16 位数字）时，总共有多少种方案？

解题思路

本题本质上是一个因数分解与排列组合问题。我们需要找到所有满足 $L \times W \times H = n$ 的有序三元组 $(L, W, H)$ 的数量。

核心步骤

  1. 分解因数：首先求出 $n$ 的所有因数。
  2. 枚举求解：通过枚举因数作为 $L$，再在 $n/L$ 的因数中枚举 $W$，从而确定 $H$。
  3. 计数逻辑：
    • 如果 $L, W, H$ 互不相同，则有 $6$ 种排列（$A_3^3$）。
    • 如果其中两个相同（如 $L=W \neq H$），则有 $3$ 种排列。
    • 如果三个都相同（$L=W=H$），则有 $1$ 种排列。

为了优化性能，我们在枚举 $L$ 时只需遍历到 $\sqrt{n}$，这已经覆盖了所有不重复的“形状”组合，再通过数学方法计算排列数即可。

题目来源：蓝桥杯练习系统。

给定一个长度为 $n$ 的 01 字符串，其中部分位置标记为 ?。这些位置可以任意填充 0 或 1。请问如何填充这些位置，使得该 01 字符串中出现互不重叠的 00 和 11 子串数量最多？请输出这个最大数量。

输入格式

输入一行，包含一个由 0、1 和 ? 组成的字符串。

输出格式

输出一行，包含一个整数，表示能够组成的互不重叠的 00 或 11 子串的最大个数。

样例输入

样例解析

对于样例输入 1110?0，我们可以尝试不同的填充策略：

  • 若将 ? 填为 1，字符串变为 111010，最多包含 1 个 11 子串。
  • 若将 ? 填为 0，字符串变为 111000。
    • 可以找到 11（索引 0-1）和 00（索引 3-4 或 4-5）。
    • 由于子串不能重叠，例如选择了索引 3-4 的 00，则索引 4 不能再参与其他配对。
    • 最优解为 2 个子串（例如 11 和 00）。

因此，最大个数为 2。

解题思路

1. 暴力枚举的局限性

最直观的思路是暴力搜索。假设字符串中有 $m$ 个 ?，每个 ? 有 2 种填法，则总共有 $2^m$ 种可能的字符串。对于每种字符串，再遍历统计最大子串数。
缺点：当 $m$ 较大时（例如 $m=20$），计算量将突破百万级，导致超时。暴力法在此题中不可行。

2. 贪心策略

我们需要寻找一种局部最优策略，使得全局结果达到最优。

核心思考：如果我们正在处理某个位置 $i$，它是否应该与前面的位置 $i-1$ 配对，还是留给后面的位置 $i+1$ 配对？

贪心原则：优先与前面的字符配对。

理由：

  • 如果位置 $i$ 选择和 $i-1$ 配对，那么位置 $i$ 被占用，无法再与 $i+1$ 配对。
  • 如果位置 $i$ 选择不和 $i-1$ 配对，而是等待与 $i+1$ 配对，那么位置 $i-1$ 可能就永远无法配对了（因为 $i$ 是它唯一的机会）。
  • 显然，“确保前面的字符有机会配对”比“赌后面的字符能配对”更稳妥。因为配对成功就能贡献 +1 的价值，尽早拿下已知的收益是贪心的精髓。

具体操作：

  1. 从左到右遍历字符串。
  2. 维护一个数组或标记，记录每个位置是否已被使用。
  3. 对于位置 $i$：
    • 如果 $i$ 或 $i-1$ 已被使用，则跳过。
    • 如果字符相同（或者是 ? 通配），则配对成功，标记 $i$ 和 $i-1$ 为已使用，答案 +1。
    • 如果不能与前配对，则暂时保留，等待后续处理（实际上在遍历过程中，不与前配对自然就留给了后面，但逻辑上我们只需每一步看前面即可）。

关于 ? 的处理：

  • ? 是万能字符。
  • 如果当前字符是 ?，只要前一个字符存在且未被占用，就可以强制填充为与前一个字符相同的值，完成配对。
  • 如果当前字符是确定值（0 或 1），则必须前一个字符与之相同才能配对。

初始化为False，表示所有位置均未被匹配

for i in range(len(s)):

# 如果当前位置已经被匹配过，跳过
if li[i]:
    continue

# 尝试与前一个位置(i-1)匹配
if i - 1 >= 0 and not li[i - 1]:

    # 此时'?'可以变成任意字符，必然能和当前字符匹配
    if s[i - 1] == '?':
        matched = True
    # 情况2: 当前字符是 '?'
    # 此时'?'可以变成前一个字符，必然能匹配
    elif s[i] == '?':
        matched = True
    # 情况3: 两个字符都是确定值且相等
    elif s[i] == s[i - 1]:
        matched = True

    if matched:
        li[i] = True
        li[i - 1] = True
        ans += 1
        # 匹配成功后，当前位置i已使用，无需再向后匹配
        continue

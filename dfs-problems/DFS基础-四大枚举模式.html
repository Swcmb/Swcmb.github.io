B3621 枚举元组

题目描述

$n$ 元组是指由 $n$ 个元素组成的序列。例如 $(1,1,2)$ 是一个三元组、$(233,254,277,123)$ 是一个四元组。

给定 $n$ 和 $k$，请按字典序输出全体 $n$ 元组，其中元组内的元素是在 $[1, k]$ 之间的整数。

「字典序」是指：优先按照第一个元素从小到大的顺序，若第一个元素相同，则按第二个元素从小到大……依此类推。详情参考样例数据。

输入格式

输出格式

若干行，每行表示一个元组。元组内的元素用空格隔开。

说明/提示

对于 $100\%$ 的数据，有 $n\leq 5, k\leq 4$。

一、思路从哪里来？

题目要求按字典序输出所有长度为 (n)、每个位置都取 (1 \sim k) 的元组。其实就是从 (k) 个数字中可重复地选出 (n) 个，组成序列。
数据范围 (n \le 5)，(k \le 4)，最多只有 (4^5 = 1024) 种情况，直接穷举即可。

怎么想到 DFS 的？

  • 构造一个元组可以看作逐位填充的过程：先填第 1 位（有 (k) 种选择），再填第 2 位……直到填满 (n) 位。
  • 这恰好形成一棵 “决策树”（状态空间树），树的深度是 (n)，每个结点有 (k) 个分支，分别对应这一位可以填的 (k) 个数字。
  • 对这棵树的深度优先遍历就是 DFS。在遍历过程中，只要沿着每一条从根到叶子的路径，把路径上的数字收集起来，就得到了一个完整的元组。
  • 又因为我们对每一位从小到大尝试数字（1→k），所以 DFS 的访问顺序天然就是字典序。

因此，用递归实现的 DFS（回溯法）是解决本题最清晰、自然的方法。

二、详细解释

1. 状态定义

  • 递归函数：dfs(pos, current)
    • pos：当前正在填充第 pos 位（从 0 开始计数）。
    • current：一个列表，存放已经填好的前 pos 个数字。
  • 初始状态：pos = 0，current = []。

2. 递归终止条件

  • 当 pos == n 时，说明已经填满了 (n) 位，current 就是一个完整的元组。将其用空格分隔打印即可。

3. 搜索与回溯

对于第 pos 位，循环尝试数字 i 从 1 到 k：

  1. 做选择：把 i 加入到 current 末尾。
  2. 进入下一层：调用 dfs(pos + 1, current) 去决定下一位。
  3. 撤销选择（回溯）：调用结束后，把刚加入的 i 从 current 中移除，以便尝试下一个数字。

这一步”退回来”的操作就是回溯，它保证了每一层的选择互不干扰，可以完整遍历所有分支。

4. 如何保证字典序？

正是因为我们在每一位上都是从 1 到 k 依次尝试，所以在树的同层中，左边分支的值总是小于右边分支。DFS 优先走左边，因此输出顺序就是字典序。

四、复杂度说明

  • 时间复杂度：共有 (k^n) 个元组，每个元组输出时需 (O(n)) 时间，总复杂度为 (O(n \cdot k^n))。
    本题 (n\le5, k\le4)，最大运算量约为 (5 \times 1024 = 5120) 步，完全可行。
  • 空间复杂度：递归深度为 (n)，result 列表也最多存 (n) 个元素，故为 (O(n))。

B3622 枚举子集（递归实现指数型枚举）

题目描述

今有 $n$ 位同学，可以从中选出任意名同学参加合唱。

请输出所有可能的选择方案。

输入格式

仅一行，一个正整数 $n$。

输出格式

若干行，每行表示一个选择方案。

每一种选择方案用一个字符串表示，其中第 $i$ 位为 Y 则表示第 $i$ 名同学参加合唱；为 N 则表示不参加。

需要以字典序输出答案。

输入输出样例 #1

输入 #1

输出 #1

说明/提示

对于 $100\%$ 的数据，保证 $1\leq n\leq 10$。

一、思路从哪里来？

题目要求按字典序输出所有由 ‘N’ 和 ‘Y’ 组成的长度为 (n) 的字符串。
每个位置有两种可能：’N’（不选）或 ‘Y’（选）。这恰好是一个逐位决策的过程：先决定第 1 位，再决定第 2 位……直到第 (n) 位。

怎么想到 DFS？

  • 把所有可能的字符串看作一棵二叉树（决策树），树的深度为 (n)，每个结点有两个分支：左分支表示该位填 ‘N’，右分支表示该位填 ‘Y’。
  • 对树进行深度优先遍历（DFS），每一条从根到叶子的路径就对应一个完整的方案，路径上的选择依次组成字符串。
  • 为了让输出满足字典序，我们规定优先走左分支（’N’），再走右分支（’Y’）。这样 DFS 先产生的方案第一位都是 ‘N’，后产生的第一位都是 ‘Y’，且每一位都符合字典序，整体输出自然就是字典序。

由于 (n\le10)，方案总数最多 (2^{10}=1024)，DFS 完全可以胜任。这种方法通常被称为递归实现指数型枚举。

二、详细解释

1. 状态定义

递归函数：dfs(pos, current)

  • pos：当前正在决定第 pos 位（从 0 开始计数）。
  • current：一个字符列表，存放已经生成的前 pos 个字符（’N’ 或 ‘Y’）。

初始调用：dfs(0, [])。

2. 递归终止条件

当 pos == n 时，说明 (n) 位全部决定完毕。此时 current 中恰好有 (n) 个字符，将它们拼接成字符串输出即可。

3. 搜索与回溯（逐位决策）

对于第 pos 位，有两种选择：

  1. 选 'N'：将 'N' 加入 current，递归进入 dfs(pos + 1, current)，决定下一位。递归返回后，将刚加入的 'N' 移除（回溯），恢复状态，以便尝试下一种选择。
  2. 选 'Y'：将 'Y' 加入 current，递归进入 dfs(pos + 1, current)，返回后同样移除 'Y'。

注意：因为 'N' < 'Y'，我们先尝试 ‘N’，后尝试 ‘Y’，这样生成的字符串顺序一定是字典序。

以 (n=2) 为例，决策树如下：


顺序为 NN, NY, YN, YY，符合字典序（’N’ < ‘Y’）。

四、复杂度说明

  • 时间复杂度：共 (2^n) 种方案，每种方案输出长度为 (n) 的字符串，总复杂度为 (O(n \cdot 2^n))。对于 (n\le10)，最大运算量约 (10 \times 1024 = 10240)，非常快。
  • 空间复杂度：递归深度为 (n)，current 列表最多存 (n) 个字符，故空间复杂度为 (O(n))。

B3623 枚举排列（递归实现排列型枚举）

题目描述

今有 $n$ 名学生，要从中选出 $k$ 人排成一列拍照。

请按字典序输出所有可能的排列方式。

输入格式

仅一行，两个正整数 $n, k$。

输出格式

若干行，每行 $k$ 个正整数，表示一种可能的队伍顺序。

输入输出样例 #1

输入 #1

输出 #1

说明/提示

对于 $100\%$ 的数据，$1\leq k\leq n \leq 10$。

一、思路从哪里来？

题目要求从 (n) 名学生中选出 (k) 人排成一列，按字典序输出所有可能的队伍顺序。
这不再像元组那样允许元素重复，而是排列型枚举：选出的 (k) 个人互不相同，且顺序重要。

怎么想到 DFS？

  • 可以把排队伍看作逐位选择的过程：先挑第 1 个人（从还没被选的人里挑），再挑第 2 个人……直到挑满 (k) 人。
  • 这就形成了一棵决策树，深度为 (k)。每层的分支取决于当前还有哪些学生没被选。DFS 沿着每一条路径走到底，便得到一个完整的排列。
  • 为了保证字典序，我们在每一层都按学生编号从小到大去尝试那些未被选过的人。
  • 需要用一个标记数组记录某个学生是否已经在队伍中，选择时检查，选完后标记，返回时取消标记（回溯）。

数据范围 (n \le 10)，总方案数最多为 (P(10,5) = 10 \times 9 \times 8 \times 7 \times 6 = 30240)（实际上 (k \le n \le 10)，最大排列数 (10! = 3,628,800) 也在可接受范围内），DFS 完全可行。

二、详细解释

1. 状态定义

递归函数：dfs(pos, current)

  • pos：当前正在安排第 pos 个位置（从 0 开始计数）。
  • current：列表，存放已经排好的前 pos 个人的编号。
  • 额外全局数组：used[i] 为布尔值，表示编号为 i 的学生是否已被选入队伍。

初始状态：pos = 0，current = []，used 全为 False。

2. 递归终止条件

当 pos == k 时，说明已经选满了 (k) 个人。此时 current 就是一个完整的排列，直接输出即可。

3. 搜索与回溯

对于第 pos 个位置，循环尝试学生编号 i 从 1 到 n：

  1. 检查：如果 used[i] 为 True，说明该学生已经在队伍中，跳过。
  2. 做选择：将 i 加入 current，并标记 used[i] = True。
  3. 进入下一层：递归调用 dfs(pos + 1, current)，决定下一个位置。
  4. 撤销选择（回溯）：递归返回后，将 i 从 current 中移除，并恢复 used[i] = False，以便尝试下一个学生。

4. 如何保证字典序？

因为我们在每一位上都是从 1 到 n 按顺序尝试，并且只挑选未被使用的人，所以先出现的排列，其靠前位置上的数字必然更小。这天然就符合字典序。

以 n=3, k=2 为例，决策树如下：

  • 第1位尝试 1：第2位可尝试 2 → 输出 1 2；尝试 3 → 输出 1 3。
  • 回溯后第1位尝试 2：第2位可尝试 1 → 输出 2 1；尝试 3 → 输出 2 3。
  • 第1位尝试 3：第2位可尝试 1 → 输出 3 1；尝试 2 → 输出 3 2。
    输出顺序 1 2, 1 3, 2 1, 2 3, 3 1, 3 2 完美符合字典序。

三、Python 代码

四、复杂度说明

  • 时间复杂度：排列总数为 (P(n,k) = \frac{n!}{(n-k)!})，每个排列输出时需要 (O(k)) 时间，总复杂度为 (O(k \cdot P(n,k)))。最大 (n=k=10) 时，(10! = 3,628,800)，大约 3600 万次操作，仍可在 1 秒内完成。
  • 空间复杂度：递归深度为 (k)，current 列表最多存 (k) 个元素，used 数组大小为 (n+1)，总空间 (O(n))。

你问的”决策树是怎么画的”，其实就是在问：如何把 DFS 的搜索过程画成一棵树，以便直观理解代码的递归结构。

在回溯算法中，我们通常把状态（已经做了哪些选择）看作树的节点，把下一步可以做的选择看作从该节点伸出的边。从根到叶子的一条完整路径，就对应一个完整的解。

下面结合你之前问的三个题目，给出每种问题的决策树画法，并总结通用步骤。

一、枚举元组（B3621）：完全 k 叉树

题目：n=2, k=3，输出 (1,1) 到 (3,3)。
特点：每个位置的选择独立，且可以重复，所以每个节点都有 k 个相同的分支。

画法要点：

  • 树深度 = n = 2。
  • 根节点表示还没选任何数，状态为空。
  • 每层节点都向下分出 k 条边，边上的标签就是该位选择的数字。
  • 叶子节点就是完整元组，从根到叶子的路径依次读取数字得到元组。
  • 为了字典序，我们在每个节点都从左到右依次尝试 1,2,…,k。

二、枚举子集（B3622）：二叉树

题目：n=3，输出 NNN 到 YYY。
特点：每个位置只有两种选择（N或Y），所以是一棵标准的二叉树，深度为 n。

画法要点：

  • 左分支表示填 ‘N’，右分支表示填 ‘Y’。
  • 因为 ‘N’ 字典序小于 ‘Y’，我们规定先走左子树，再走右子树，这样 DFS 输出的顺序就是字典序（深度优先遍历：先访问左子树所有叶子，再访问右子树所有叶子）。
  • 所有叶子都在第 n 层，每个叶子对应一个完整字符串。

三、枚举排列（B3623）：分支数递减的树

题目：n=3, k=2，输出 1 2, 1 3, 2 1, 2 3, 3 1, 3 2。
特点：不能重复选同一个人，所以每一层可选的数字集合是上一层选择后剩下的。

画法要点：

  • 根节点可选所有人（{1,2,3}），分出 3 条边。
  • 第一层选 1 后，该节点剩余可选集变为 {2,3}，因此它分出 2 条边。
  • 第一层选 2 后，剩余可选集为 {1,3}，同样分出 2 条边。
  • 因为树深度 k=2，所以到第二层（第2位）时已经到达叶子，直接输出当前路径上的选择。
  • 为了保证字典序，每个节点的子节点（可选数字）要从小到大排列。

四、如何自己画决策树？通用步骤

  1. 确定树的深度：
    问题要求我们做多少次决策，树的深度就是多少。

    • 元组：n 次决策，深度 n。
    • 子集：n 次决策，深度 n。
    • 排列：k 次决策，深度 k。

  2. 确定根节点状态：
    表示”尚未做出任何选择”。可以画一个空心圆或标注”start”。

  3. 确定每个节点的分支（可选选择）：

    • 元组：每个节点都有 k 种选择（1~k）。
    • 子集：每个节点有两种选择（N / Y）。
    • 排列：当前节点可选数字 = 全集 \ {已经选过的数字}，分支数 = 剩余可选数字个数。

  4. 画出树枝并标注选择值：
    从父节点向下引出分支，在分支上写当前决策的值（数字或字符）。

  5. 按字典序排列子节点：
    为了保证输出顺序，必须让值小的分支排在左边，值大的排在右边。画树时从左到右就是数字或字符的递增顺序。

  6. 叶子节点标记完整结果：
    当深度达到预定值时，将路径上的所有选择组合起来，写在叶子旁边。也可以把叶子画成一个实心圆点。

五、决策树与 DFS 代码的对应关系

  • “进入左子树” 对应代码里的 append + dfs(pos+1)
  • “从子树返回” 对应 pop()（回溯）
  • “遍历所有兄弟分支” 对应 for i in range(...): 循环

只要按照这种树结构去模拟，你写出的 DFS 代码自然就是正确的，且能保证字典序输出。

如果以后遇到新的回溯问题，不妨先手工画一棵小规模的决策树，再根据树的结构写出递归框架。这是非常有效的解题思维。

P10448 组合型枚举

题目描述

从 $1 \sim n$ 这 $n$ 个整数中随机选出 $m$ 个，输出所有可能的选择方案。

输入格式

两个整数 $n, m$ ,在同一行用空格隔开。

输出格式

按照从小到大的顺序输出所有方案，每行 $1$ 个。

首先，同一行内的数升序排列，相邻两个数用一个空格隔开。

其次，对于两个不同的行，对应下标的数一一比较，字典序较小的排在前面（例如 1 3 5 7 排在 1 3 6 8 前面）。

一、思路从哪里来？

题目要求从 (1\sim n) 中选出 (m) 个数，内部升序，方案间字典序。
这不同于排列（排列顺序重要，元素可以任意排列），组合要求选出的集合无序，但输出时要求按升序排列，并且方案按字典序排列。

怎么想到 DFS？

  • 我们可以把”选出 (m) 个数”的过程看作逐个确定组合中的每个数：先确定第 1 个数，再确定第 2 个数……直到选满 (m) 个。
  • 为了保证组合内部升序且不重复，我们强制规定：后面选的数必须比前面选的数大。这样就自然避免了 {1,2} 和 {2,1} 这种重复。
  • 这又是一个典型的决策树：深度为 (m)，每一层选择一个比上一个大、且不超过 (n) 的数。DFS 遍历这棵树就能不重不漏地生成所有组合。
  • 在每一层，我们从”上个数 +1”开始尝试，按从小到大的顺序枚举候选值，这样生成的组合字典序天然正确（先尝试的数越小，整个组合的字典序越靠前）。
  • 加上剪枝：如果剩余的数字个数不足以选出还需要的数，就提前停止循环，提高效率。

数据范围 (n+(n-m)\le 25)，意味着最大组合数可能达到 (C(25,12)\approx 5\times 10^6)，虽然数量较大，但 DFS 的回溯框架仍可解决，加上输出量较大，需要注意 I/O 效率。

三、详细解释

1. 状态定义

递归函数：dfs(pos, start)

  • pos：当前正在确定组合中的第 pos 个数（从 0 开始，pos 取值范围 0 到 m-1）。
  • start：当前这个数的最小允许值（因为组合要升序，它必须大于前一个选的数）。一开始 start = 1。
  • 全局列表 current：存储当前已选的数。

2. 递归终止条件

  • 当 pos == m 时，表示已经选够了 (m) 个数，current 中就是一个完整的组合，输出即可。

3. 搜索与剪枝

对于当前位置 pos，我们需要选第 pos+1 个数：

  • 候选数字的范围：从 start 到 n。
  • 剪枝：如果我们还需要选 m - pos 个数，那么当前选的数字 i 必须满足：选了 i 之后，剩下的数字（i+1 到 n）个数必须 >= m - pos - 1（因为还需要选这些数）。即：
    [
    n - i \ge m - pos - 1 \quad\Rightarrow\quad i \le n - (m - pos) + 1
    ]
    所以循环的上限应为 min(n, n - (m - pos) + 1)，实际上上限就是 n - (m - pos) + 1。
  • 遍历 i 从 start 到上限：
    1. 做选择：current.append(i)
    2. 进入下一层：dfs(pos + 1, i + 1)，因为下一个数必须大于 i。
    3. 撤销选择（回溯）：current.pop()
  • 因为我们在 i 的循环中是从小到大枚举的，所以生成的组合会符合字典序（先固定小的数，后面的数也会尽可能小）。

4. 字典序保证

假设有两个组合 A = a1 a2 ... am 和 B = b1 b2 ... bm。DFS 按照”先选较小的 a1，再选较小的 a2…”的顺序生成叶子节点。在决策树上，这就是从左到右的深度优先遍历。因此输出的顺序必然满足题目要求的字典序（比较第一个不同数字的大小）。

五、复杂度说明

  • 时间复杂度：生成的组合数量为 (C(n, m))，每个组合需要 (O(m)) 的时间构造和输出，总复杂度为 (O(m \cdot C(n, m)))。在极端情况下 (n=25, m=12) 时 (C(25,12)=5200300)，输出量较大，Python 可能需要使用 sys.stdout.write 等优化，但题目保证 n+(n-m) ≤ 25 实际上意味着 (n\le 25) 且 (m) 与 (n) 的差值不大，组合数可能不会到五百万，一般可接受。如果担心效率，可将输出换成 sys.stdout.write(' '.join(map(str, current)) + '\n')。
  • 空间复杂度：递归深度为 (m)，current 列表存储 (m) 个元素，总空间 (O(m))。剪枝数组无额外开销。

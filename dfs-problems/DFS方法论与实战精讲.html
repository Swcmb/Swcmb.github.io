DFS 方法论与实战精讲

一、DFS 解题流程步骤

无论是排列、组合、图搜索还是约束满足问题，DFS 的实现几乎都遵循下面六个步骤。

  1. 问题建模，画出决策树

    • 弄清每一层要“决策”什么：是选一个数字？填一个格子？还是走一步图？
    • 手动画出小规模情况下的树状图，明确深度、分支、叶子节点的含义。

  2. 定义核心状态

    • 找出递归过程中需要维护的变量，通常包括：
      • 当前进度（如已选数字个数 pos、搜索深度 depth、当前坐标 (x, y)）
      • 当前局面（如已排列的列表 current、已用数字标记 used、已访问标记 visited）
      • 资源剩余量（如剩余苹果 remain、剩余火柴棍 total）
    • 状态越精简，回溯越容易。

  3. 设计递归函数 dfs(...)

    • 参数必须能完整描述当前决策点，方便在不同分支间传递和恢复。
    • 常见参数：进度指针 idx、上一层的限制 last、当前累计值 cur_sum 等。

  4. 编写终止条件

    • 达到目标状态（如凑满总和、走完所有格子、排列长度已满）时，执行输出、计数或更新最优解，然后 return。
    • 有时需要额外验证（如哈密顿回路最后能否回到起点）。

  5. 枚举当前层的所有选择，并剪枝

    • 用 for 或方向数组列举所有可能的分支。
    • 在递归前加入可行性/合法性判断，不满足的立即 continue 或 return（剪枝）。
    • 保证选择顺序满足题目要求（如字典序、非递减）。

  6. 做出选择 → 递归下一层 → 撤销选择（回溯）

    • 做选择：修改状态（加入元素、标记已用、更新剩余量等）。
    • 递归：调用 dfs(新状态)。
    • 撤销选择：将状态还原到递归前的样子（弹出元素、取消标记、恢复剩余量）。
    • 如果找到唯一解就立即返回 True 并向上传递，可以提前结束。

一句话模板：
定义状态 → 终止条件 → 枚举选择（+剪枝） → 递归 → 回溯。

二、常见剪枝技巧

从你提供的题目中可以归纳出以下几类非常实用的剪枝方法，它们能让 DFS 从“暴力枚举”变为高效算法。

剪枝类型 核心思想 题目实例
可行性剪枝 预先判断当前局面下能否达到目标，若不能则直接回溯。 分糖果：剩余总量必须在 2×剩余人数 到 5×剩余人数 之间，否则停止。自然数拆分：下一个数必须 ≤ n - cur_sum。
重复性避免（顺序剪枝） 强制选择序列有序（非递增或非递减），消除因顺序不同造成的重复。 放苹果：a1 ≥ a2 ≥ ... ≥ an。整数拆分：后选的数 ≥ 前一个数。
上下界约束 直接限制枚举范围，避免无效循环。 火柴棍等式：总棍数超过 total 就不再延伸数字。自然数拆分：i 从 start 到 n - cur_sum。
已访问标记（避免环） 在图/网格搜索中，用 visited 数组避免重复访问或死循环。 星空星座、扫雷3bv、全O全X回路、最大编号点。
最优性剪枝 当前解已不可能优于已知最优解时，停止探索该分支。 九位数订单编号：虽然未显式剪枝，但可以加入“即使后面全选最大公约数也超不过 best_gcd”的判断。
特殊状态快速处理 某些状态可直接得出结果，避免不必要的递归。 放苹果：remain == 0 时直接计数返回，不再枚举后续盘子。图可达性优化：反向建图 + 编号从大到小一次遍历，相当于全局剪枝。

注意：剪枝的顺序很重要，越早剪枝，效率提升越大。通常把最可能失败的条件放在最前面判断。

三、DFS 题型分类（附对应题目）

根据你给出的所有例子，可以把常见的 DFS 应用场景归为五大类。掌握每一类的套路后，新题来了基本就能对号入座。

1. 排列型 / 组合型枚举

特征：从有限集合中按一定规则选取元素排列或组合，决策树清晰，深度固定。
关键点：使用 used 标记或 start 索引避免重复；常需有序性保证不重不漏。
例题对应：

  • 全排列 → 九位数订单编号（1~8 排列）
  • 可重复组合（非递减） → 自然数拆分
  • 整数划分（非递增） → 放苹果
  • 定和分配（带人数限制） → 分糖果

2. 图 / 网格遍历型

特征：在显式的图（邻接表）或隐式图（二维网格）上搜索路径、连通区域或可达性。
关键点：visited 标记，方向数组，栈模拟防溢出。
例题对应：

  • 连通块计数 → 星空星座、扫雷3bv（统计“空”）
  • 可达性查询 → 求每个点能到达的最大编号点
  • 找特定路径（哈密顿） → 全O全X回路（超立方体上的哈密顿回路）

3. 约束满足 / 回溯型（填数类）

特征：在棋盘或表格中填入数字，满足行列区域不重复等约束。
关键点：多条件合法性校验，按空位顺序尝试，失败即回溯。
例题对应：

  • 4×4 数独 → 数独填数（行、列、宫唯一）
  • 典型扩展：N皇后，也是此类。

4. 构造枚举型（生成所有可能项）

特征：按数位或组成部分逐位生成所有可能的对象（如整数、字符串），再筛选或验证。
关键点：递归构建时传递累计值，利用资源上限剪枝。
例题对应：

  • 火柴棍等式 → DFS 生成所有符合棍数限制的整数，再暴力配对验证。

5. 最优解搜索型

特征：在所有方案中寻找满足某一最优条件的解（最大值、最小值、字典序最小等）。
关键点：维护全局最优变量，在叶子节点处更新，可配合最优性剪枝。
例题对应：

  • 最大公约数最大且数字最小 → 九位数订单编号（结合排列枚举）

总结

步骤 做什么
建模 理解决策树，明确每一步的抉择
状态与参数 确定递归函数参数，精简状态
终止条件 何时算一个完整解，如何处理
枚举 + 剪枝 循环所有分支，用可行性、有序性、上下界等提前阻断无效路径
递归 + 回溯 更改状态 → 进入下一层 → 恢复状态，保证不同分支互不干扰
输出/返回 按要求输出全部解、计数、或最优解

常见剪枝：可行性、有序性、上下界、visited 标记、最优性、特殊状态快速通道。
五大题型：排列组合枚举、图/网格遍历、约束满足（回溯）、构造枚举、最优解搜索。

只要把上述流程刻在脑子里，再遇到 DFS 题目时，你就可以快速画出决策树、写出框架，然后针对具体问题嵌入剪枝逻辑，高效通过。

一、思路从哪里来？

题目要求构造一个九位数：先用 1~8 排列成一个八位数，再任选一个位置插入一个 1~8 的数字。所有可能的订单编号中，找出与给定的 (n) 的最大公约数最大的那个，若最大值有多个，取数值最小的编号。

怎么想到 DFS？

  • 构造过程的第一步是“生成 1~8 的全排列”。这是一个典型的排列型枚举问题，与之前“选学生排成一列”的 DFS 完全相同：每次从未使用的数字中选一个，直到选出 8 个数，形成一种排列。
  • 决策树深度为 8，每层分支数为当前剩余可选数字的个数，通过 used 数组标记使用状态，回溯尝试所有可能。
  • 得到一种排列后，再枚举“插入位置”（0~8，共 9 个）和“插入数字”（1~8），组合出所有九位数，计算 GCD 并更新当前最优解。

因为总排列数只有 (8! = 40320) 种，每种排列组合出 (9\times8 = 72) 个九位数，总计约 290 万个候选，完全可以暴力枚举。DFS + 回溯是最直接、最清晰的实现方式。

二、决策树怎么画

以生成 1~3 的排列（简化）为例，原理与 1~8 完全一致：

  • 深度 = 8，每层按 1~8 的顺序尝试未使用数字。
  • 叶子节点（排列生成完毕）附加循环：枚举插入位置和插入数字，计算九位数的 GCD。

因为 DFS 先尝试小的数字，所以生成的排列是按字典序的。然而最终筛选的九位数大小还受插入操作影响，不能直接保证九位数的最小性，因此需要完整比较所有候选值。

一、思路从哪里来？

题目本质：有 (n) 个位置，每个位置可以是 O（空）或 X（盖住），一共 (2^n) 种状态。要求构造一个操作序列，从全 O 开始，每次只改变一个位置（盖住一个空，或揭开一个盖住的），使得每个状态恰好出现一次，最后回到全 O。

把每种状态看作一个点，如果两个状态只差一位，就连一条边。问题就变成：在这个 (n) 维超立方体图上，找一条从全 0 出发、经过所有顶点恰好一次，最后回到全 0 的回路——也就是 哈密顿回路。

怎么想到 DFS 的？

  • 这是一个经典的“是否存在哈密顿回路”问题，可以用 深度优先搜索（回溯法） 尝试构造路径。
  • 从起点（全 O）开始，每步尝试改变其中一个位置（翻转），得到一个新的状态。如果这个新状态之前没有访问过，就继续往下走。
  • 如果某一步发现所有邻居都已访问过，就撤销这一步（回溯），退回去尝试其他分支。
  • 当访问过的状态数达到 (2^n) 时，检查当前状态是否与起点（全 O）相邻（即能否一步回到起点）。如果能，则找到完整回路；否则继续回溯。

由于 (n \le 15)，状态总数最大为 (32768)，回溯 DFS 在合理剪枝下可以很快找到一条合法路径。（实际上，(n) 维超立方体一定存在哈密顿回路，这其实就是 格雷码，但题目不要求最优解法，回溯实现完全可以接受。）

题目描述中“似乎只能向上回溯一次”可能是误解——回溯法会重复“前进-撤销”的过程很多次，直到找到完整回路。所谓“一次”可能是指某个局部感觉，但整体回溯次数可以很多。

三、详细解释

1. 状态表示

用整数 (s) 的二进制位表示 (n) 个洞的状态：0 对应 O（空），1 对应 X（盖住）。初始状态 (s = 0)（全 O）。

2. 全局变量

  • n：洞的数量
  • total = 1 << n：状态总数 (2^n)
  • visited：布尔数组，大小 (2^n)，标记某个状态是否已在当前路径中
  • path：列表，存储已经过状态的顺序（整数）

3. DFS 函数

dfs(state, depth)：

  • state：当前状态
  • depth：已经访问的状态个数（包含当前状态）

终止条件：

  • 如果 depth == total，说明已经走完了所有状态。检查 state 能否一步回到 0（全 O），即 state 的二进制中只有 1 位是 1（或者说 state 是 2 的幂，包括 state == 1,2,4,...）。如果可以，则找到解，返回 True。
  • 否则，继续探索。

递归过程：

  • 循环 i 从 0 到 n-1，尝试翻转第 i 位：next_state = state ^ (1 << i)
  • 若 not visited[next_state]：
    1. 标记 visited[next_state] = True
    2. 将 next_state 加入 path
    3. 递归调用 dfs(next_state, depth + 1)
    4. 如果递归返回 True，说明已经找到解，直接向上返回 True
    5. 否则，回溯：撤销标记 visited[next_state] = False，从 path 中移除 next_state，继续尝试下一个 i。
  • 如果所有 i 都尝试完仍未找到解，返回 False。

4. 主流程

  • 初始化 visited[0] = True，path = [0]
  • 调用 dfs(0, 1)
  • 找到解后，将 path 中的每个整数转化为长度为 n 的 O/X 字符串输出，最后额外输出一行全 O（因为要回到起点，题目要求最后一行也是全 O）。

5. 为什么能保证输出合法序列？

  • 每次只改变一位，相邻状态在路径中相邻。
  • visited 数组确保每个状态只出现一次。
  • 最后一步回到全 0，满足“回到初始状态”的要求。

四、你的“只能向上回溯一次”误解说明

回溯法的本质是 “试错—撤销—再试” 的反复过程。
你可能会在某个状态发现所有邻居都走过了，于是必须退回上一层（撤销刚才选择的那一步），再尝试该层的其他分支。这整个过程可能会在深层和浅层之间来回多次，直到找到完整回路。因此，并不是“只能回溯一次”，而是会回溯很多次，直到所有可能性都被尝试或找到解。DFS 回溯框架完全能胜任此题。

  • 当前盘子放的苹果数 i 从 min(remain, last) 向下枚举到 0（从大到小尝试，确保非递增）。
  • 对于每个 i：
    1. 做选择：无显式改变，直接递归。
    2. 进入下一层：dfs(disk + 1, remain - i, i)。
    3. 因为只需计数，无需回溯任何全局状态，递归传递值即可。

4. 为什么枚举顺序能保证无重复？

强制了 (a_1 \ge a_2 \ge \dots \ge a_n)，任何合法的无序分配都可以唯一地排列成这种形式。我们恰好枚举了所有这样的非递增序列，所以答案正确。

详细解释：怎么想到反向建图优化？

一、原问题的本质

题目：给定有向图，对于每个点 (v)，求从 (v) 出发能到达的编号最大的点。

朴素做法：对每个点做一次 DFS，统计能到达的所有点，记录最大值。复杂度 (O(N(N+M)))。

当 (N, M) 达到 (10^5) 或更大时，朴素做法会超时，因此我们需要更快的优化。

二、关键洞察：从“我能到谁”变为“谁能到我”

原问题中，我们站在起点 (v)，关心的是我能到达谁，然后在这些“谁”里找最大编号。
这种“向外扩散”的搜索，对于每个起点都要做一次，导致大量重复探索。

反过来想：

  • 如果我知道某个大编号点 (x) 能被哪些起点到达，那么这些起点的答案至少是 (x)（可能还有更大的）。
  • 如果我们按编号从大到小处理这些大编号点，并“通知”所有能到达它的起点，那么这些起点的答案一被确定，后面就不用再搜它们了。

这就是反向建图的核心思想：
原图边 (u \to v) 表示“(u) 能到 (v)”。
反向图边 (v \to u) 表示“(v) 能被 (u) 到达”，等价于“哪些点能到达 (v)”。

从大编号点在反图上 DFS，访问到的所有点，都是在原图中能到达这个大编号点的。这样，我们就一次性确定了这些点的答案（至少是这个大编号），并且由于我们按编号从大到小处理，早确定的就是最终答案（因为更大的不会再出现了）。

反图的含义：
如果反图中存在一条从 (x) 到 (y) 的路径，说明在原图中存在一条从 (y) 到 (x) 的路径。
即：反图上 (x) 能走到的点 (y)，都是原图中能到达 (x) 的点。

2. 初始化答案数组

用 ans[1..N] 记录每个点的答案，初始为 0 表示未确定。

  • 正确性：假设某个点 (v) 在原图上能到达的最大编号是 (M_v)。
    因为 (M_v) 是 (v) 能到达的最大编号，所以在原图中存在路径 (v \leadsto M_v)。
    在反图中，这就对应着路径 (M_v \leadsto v)。

  1. 找到所有空格，并利用连通块（DFS/BFS）统计“空”的个数。
  2. 找出所有数字，检查其 8 个邻居中有没有“空格”，如果没有则计数。

为什么想到 DFS？

  • “空”是由空格组成的八连通区域，这是典型的网格连通块问题。
  • 要遍历一个连通块，自然会用到深度优先搜索（DFS）或广度优先搜索（BFS）。每从一块未访问的空格开始，沿着 8 个方向把所有相连的空格都标记为已访问，同时这个块计数 +1。
  • 决策树（搜索树）就是以起始空格为根，邻居空格为子节点，继续向四面八方扩展的树形结构。

怎么想到 DFS？

  • 我们要枚举 (A) 和 (B) 的所有可能值。可以用循环从 (0) 到某个上限逐一尝试，但更“搜索式”的做法是：把每个整数看作由若干数位构成的序列，用 DFS 逐位生成所有可能的整数。
  • 生成整数时，每次在末尾添加一个数字（(0\sim 9)），并累计已使用的火柴棍数量。若当前数字为 (0)，则只能停止（因为不允许前导零）；若不为 (0)，则可以继续添加数位，也可以选择停止，形成一个完整的数字。
  • 这构成一棵决策树：根节点表示空数字，每条边代表选择一个数字拼在末尾，路径上的火柴棍消耗累加。通过 DFS 遍历这棵树，我们可以收集所有在剩余火柴棍限制下能拼出的整数。
  • 生成所有整数后，只需双层循环枚举 (A) 和 (B)，算出 (C) 并检查火柴棍总数即可。
